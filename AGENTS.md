# Правила работы с VK Fast

## Архитектура и интерфейс

- Приложение написано на Rust с egui/eframe, без Tauri, webview и JavaScript. Единственный способ входа — QR-код, подтверждаемый в приложении VK на телефоне. Владелец удалил вход через сайт VK, VK ID OAuth и cookies из-за ненадёжности; не возвращайте их без явной просьбы.
- Загрузка своих треков: плюс слева от обновления в «Моей музыке», явный выбор MP3 и подтверждение названия/исполнителя. Файл отправляется потоком только на проверенный сервер VK без cookies/API-токена; сохранение привязано к подтверждённому аккаунту и поколению сессии. Не повторяйте автоматически запрос сохранения с неоднозначным ответом, чтобы не создавать дубликаты. Тесты не загружают настоящие файлы в VK.
- QR-вход открывается только по действию пользователя; при запуске восстанавливается сохранённая сессия. Не добавляйте чтение или импорт cookies, паролей, истории и профилей других браузеров. Данные удалённых способов входа (профиль `webview`, старый `session.json`) удаляются при восстановлении сессии.
- Декодирование Symphonia, ресемплинг Rubato, нормализация ebur128 и HLS-транспорт работают на Rust внутри процесса. Linux использует PipeWire, Windows — WASAPI. Не заменяйте PipeWire на ALSA.
- Сеть, декодирование, работа с файлами, уменьшение изображений и тяжёлые вычисления выполняются вне UI и аудиоколбэка. В аудиоколбэке запрещены выделения памяти, mutex, ожидания и I/O.
- Воспроизведение, автопереход и системные медиакоманды должны работать в фоне без фокуса окна и UI-кадров. Сохраняйте MPRIS на Linux и SMTC на Windows.
- Ручная очередь находится в `PlaybackOrder`: поддерживает повторные добавления одного трека и продолжает исходный список после них. Не подменяйте ею библиотеку или очередь текущего плейлиста. Правая панель, автопереход, горячие клавиши и системные медиакоманды должны пользоваться одним порядком воспроизведения; просмотр очереди не меняет Shuffle.
- Тексты VK, Musixmatch и Genius и очередь используют одну правую панель и открываются независимо: когда открыты оба, очередь сверху, тексты снизу, между ними перетаскиваемый разделитель. Запросы текстов выполняются в фоне только для актуального трека; анонимный токен сохраняется и переиспользуется, ограничения и капча не обходятся перевыпуском токенов. API-ключ и токен хранятся отдельно в приватном `musixmatch.json`, не попадают в логи или сборку; VK cookies и аудиоссылки во внешние источники текстов не отправляются. VK запрашивается по точному audio_id через подключённую сессию; резервный Genius запускается только при включённой настройке и не продолжает отменённые запросы.
- Сохраняйте single-instance guard до завершения приложения, включая работу без окна в трее. Второй GUI-запуск только активирует первый, до открытия настроек, сессий и аудио. Служебные CLI-проверки обходят этот guard.
- На Wayland второй запуск выводит существующее окно на месте: niri, Hyprland и sway — через их IPC по PID процесса (`niri msg`, `hyprctl`, `swaymsg`), иначе окно пересоздаётся с токеном `XDG_ACTIVATION_TOKEN` запустившего приложения (безопасный API winit). Не добавляйте unsafe-код для активации Wayland-поверхностей.
- Активация окон Windows не должна имитировать Alt/Ctrl или другие клавиши: это запускает глобальные хоткеи других приложений. Используйте прямой безопасный путь Win32 через платформенную обёртку eframe; не возвращайте вызов winit/tao focus с синтетическим вводом и не сбрасывайте состояние клавиатуры. Меню трея учитывает текущую тему Windows при открытии и сохраняет высококонтрастный режим.
- Windows OTA использует только публичный GitHub Releases API репозитория `eml3ss/vk-fast`, отдельный HTTP-клиент и точный x86-64 portable-архив. Сохраняйте проверку SHA-256/размера, ограничения распаковки и версии, явную установку пользователем, ожидание завершения родительского процесса, откат при сбое и перезапуск. Обновление заменяет только `vk-fast.exe`; сессии, выбор хранения данных, config/cache и деинсталлятор не трогает. Автопроверка включена по умолчанию; уведомление находится слева от настроек. Служебный `--apply-update` обходит GUI single-instance guard; `--update-complete` проходит его и подтверждает запуск из созданного окна.
- Текущий однофайловый OTA использует job schema 2: установку выполняет helper предыдущей версии, а подтверждает запуск новая версия. Разовый ручной переход с 0.1.x на 0.2.0 согласован пользователем; повторять такой разрыв совместимости нельзя. Начиная с 0.2.0 сохраняйте автоматический переход с предыдущих опубликованных версий: при изменении архива или протокола обеспечивайте совместимость либо автоматическую миграцию. Перед выпуском проверяйте обновление именно предыдущего опубликованного клиента новым пакетом, а не только тесты нового обновлятора. Проверки используют синтетические данные и отдельные временные папки; Windows-процессы через Wine запускаются только в изолированном префиксе.
- «Открывать ссылки VK Музыки в VK Fast» включается только переключателем в настройках: приложение становится обработчиком http/https/`vkfast` пользователя (Linux — `xdg-mime` и своя .desktop-запись, Windows — регистрация в HKCU и выбор пользователем в параметрах). Распознаются только ссылки музыки VK; остальные без открытия окна передаются сохранённому прежнему браузеру и никогда не открываются повторно через систему, чтобы не зациклиться. Ссылка уходит уже запущенному экземпляру через single-instance канал. Тесты не меняют системные обработчики ссылок.
- Главная и боковая библиотека сохраняются по аккаунту (`screen_cache`) только как отображаемые метаданные — без ключей доступа, аудиоссылок и треков — и показываются при запуске до ответа VK, который их заменяет. Чтение и запись — вне UI-потока.
- «Транслировать аудиозаписи на мою страницу» выключена по умолчанию и вызывает `audio.setBroadcast` только при включённой настройке; при выключении статус очищается. Тесты не отправляют эти запросы.
- Discord RPC — сохраняемый тумблер в общих настройках, включённый по умолчанию; явное отключение сохраняется. На паузе активность полностью очищается. Используйте локальный IPC только для Rich Presence, без OAuth, Discord-токенов, голосовых команд или публикации данных VK-сессии. Кнопка GitHub ведёт на репозиторий VK Fast; тесты используют поддельный IPC-сервер и не меняют настоящий профиль Discord.
- Поддерживайте русский и английский текст, существующую тёмную тему, синий акцент и скруглённые иконки. Меняйте только запрошенные элементы интерфейса.
- На главной показывайте не более 10 уникальных карточек недавних треков, не ограничивая этим полную историю. Повторы определяйте по точным ID и подтверждённым связям library_source_key; одинаковые названия и release_key не доказывают одинаковую запись. Сообщения в списках выравнивайте по заголовкам, сохраняя отступ нижней информации релизов. Пустой плейлист подтверждается нулевым количеством от VK, а не одним отсутствием полученных строк.
- Боковая библиотека различает плейлисты и альбомы по метаданным VK и отдельно загружает подписанных музыкальных исполнителей. Сохранение коллекций и подписки привязаны к точным ID, аккаунту и поколению сессии; рекомендации не считаются подписками. Поиск открывается и скрывается лупой, при скрытии фильтр очищается; перетаскивание коллекций сохраняет общий порядок и выключается на отфильтрованном списке.

## Данные и безопасность

- На Linux настройки и логи находятся в `$XDG_CONFIG_HOME/vk-fast` или `~/.config/vk-fast`, состояние — в `$XDG_STATE_HOME/vk-fast` или `~/.local/state/vk-fast`, кэши — в `$XDG_CACHE_HOME/vk-fast` или `~/.cache/vk-fast`. Учитывайте только абсолютные значения XDG-путей.
- На Windows получайте пути через `app_paths`: установщик выбирает независимо `config` и `cache` рядом с `.exe` либо в `%LOCALAPPDATA%\VK Fast`. Выбор хранится в `vk-fast-storage.ini` рядом с программой; без этого файла сохраняется переносимый режим. Пути не должны зависеть от рабочего каталога.
- Лимит до 5 ГиБ относится только к аудиокэшу. Кэш библиотеки, история, аватарки и обложки учитываются отдельно. Сохранённые метаданные не должны содержать аудиоссылки или ключи доступа.
- Лайки привязаны к точной паре `owner_id`/`audio_id`. Общие название, исполнитель и `release_key`/`trackPageId` не доказывают одинаковую запись: разные версии могут иметь одну страницу трека. Связь исходной записи с копией в библиотеке сохраняйте только после подтверждённой операции VK через `library_source_key`.
- Не опрашивайте размер кэша по таймеру или каждый UI-кадр. Запрашивайте его при открытии настроек и после изменения лимита или очистки.
- Сохраняйте громкость, Shuffle, режим повтора, настройки, историю, текущий трек и подтверждённую позицию, размер окна. Ошибка сетевого обновления не должна уничтожать уже сохранённые данные.
- Код подтверждения QR-входа передаётся только по действию пользователя, без сохранения или журналирования.
- Не публикуйте сессии, cookies, токены, коды входа, пароли, приватные заголовки, аудиоссылки и пользовательские файлы. В логах используйте ограниченный и фильтруемый `diagnostics::event`; не записывайте сырые ответы VK.
- Идентификация ОС во входе и User-Agent определяется целевой платформой, а не хостом кросс-компиляции.

## Проверки

- Используйте `Cargo.lock` и `--locked`. Не обновляйте зависимости без необходимости для задачи.
- Для изменений Rust выполните `cargo fmt --check`, подходящие тесты и `cargo clippy --locked --all-targets -- -D warnings`. Начинайте с затронутых модулей; полный `cargo test --locked` нужен для изменений общей логики или подготовки выпуска. Не расширяйте проверку после успешного результата без новой причины.
- Папка `vk-auth/` используется только как локальная справка; её содержимое никогда не включается в Git или выпуск.
- Тесты используют синтетические данные и временные каталоги. Они не читают реальные сессии и браузерные профили, не пишут пользовательские настройки, не меняют настоящий аккаунт VK и не запускают интерактивный вход.
- Проверки D-Bus/MPRIS запускайте в изолированной сессии, чтобы не управлять чужими плеерами. Например:

  ```sh
  VK_FAST_MEDIA_ISOLATED_TEST=1 dbus-run-session -- cargo test --locked system_media::dbus_tests::isolated_mpris_roundtrip_metadata_commands_stale_seeks_and_cleanup -- --ignored --exact --nocapture
  ```

- Ручной вход выполняет владелец аккаунта. Синтетический тест или Wine не подтверждают работу настоящего Windows-интерфейса и WASAPI.

## Сборки и зависимости

- Windows собирайте только по явному запросу и только для `x86_64-pc-windows-msvc`. Используйте `scripts/build-windows.sh` и инструкции `docs/windows.md`.
- Linux AppImage/tar.gz используют системные PipeWire, fontconfig и графические библиотеки. Не вкладывайте в них системные библиотеки, модули или linuxdeploy. Внутри остаются приложение, значок, загрузчик и сжатые обязательные уведомления. Сохраняйте базу glibc 2.39+ и проверяйте запуск с библиотеками дистрибутива.
- Windows portable ZIP содержит только `vk-fast.exe` в корне, без папок и дополнительных файлов; каталоги данных создаёт приложение. OTA принимает этот формат и прежнюю папку версии с одним приложением, сохраняя строгий список разрешённых файлов. В GitHub Releases дополнительные архивы исходников не загружайте. Сохраняйте соответствующие исходники, рецепты, ссылки и уведомления в версионированной документации репозитория.
- В GitHub Releases загружайте ровно четыре runtime-файла: Linux AppImage/tar.gz, Windows portable.zip и NSIS setup.exe. Пользователь запретил дополнительные архивы исходников в релизе; сохраняйте доступ к исходникам, рецептам и лицензиям через версионированную документацию репозитория.
- Сохраняйте локальные патчи `vendor/eframe` и `vendor/souvlaki`, их документацию, лицензии и записи `[patch.crates-io]`. Не заменяйте их зависимостями из реестра без проверки исправленного поведения.
- Не удаляйте исходные авторские уведомления, лицензии, атрибуцию встроенного кода, шрифта и зависимостей. Убирая сравнения с другими приложениями, сохраняйте обязательные юридические сведения.
- Не используйте `sudo` и не меняйте системную конфигурацию для сборки или проверки. Если не хватает системного пакета, укажите его пользователю.

## Документация и Git

- README — краткое описание для пользователей: возможности, требования, сборка и лицензия. Рабочие инструкции хранятся здесь, подробные технические сведения — в `docs/`.
- Changelog и описания релизов пишите кратко и понятно обычному пользователю: что изменилось и чем это полезно, без внутренних технических подробностей и упоминаний исходного кода или лицензий. Сведения о коде и лицензиях остаются в документации репозитория и соответствующих уведомлениях.
- По установленному владельцем процессу после завершения и проверки цельной функции создавайте содержательный коммит и отправляйте его в основную ветку `main`. Это разрешение не распространяется на незапрошенную публикацию секретов, артефактов или чужих изменений. Не дробите одну задачу на мелкие коммиты и не используйте force push.
- До коммита проверяйте diff и состав файлов. Не добавляйте `target`, `.build`, дистрибутивы, бинарники, логи, кэши, локальные SDK/toolchain, временные тестовые данные или конфигурацию личного аккаунта.
- Не отменяйте чужие изменения и не выполняйте разрушительные Git-команды без явного запроса. В итоговом сообщении сообщайте, что изменено, как проверено и какие ограничения остались.
