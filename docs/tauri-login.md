# Нативный вход и фоновый Tauri

Кнопка **«Войти через VK»** открывает форму внутри VK Fast с телефоном/почтой и паролем на одном экране. Код и подтверждение на телефоне появляются только при запросе VK. Форма поддерживает русский и английский интерфейс. QR-вход остаётся отдельным способом.

## Как проходит вход

1. По нажатию кнопки запускается скрытый Tauri-helper с собственным постоянным профилем. Он загружает обычную страницу `https://vk.ru/` и использует её настоящие формы и обработчики.
2. Плеер получает только тип текущего шага, доступные действия и состояние проверки. Значения полей, содержимое хранилищ и токены JS-мост не читает. Телефон, пароль и код передаются странице только после действия пользователя.
3. Нажатие «Войти» отправляет логин, а пароль временно остаётся в памяти этой попытки. Когда VK предлагает вход по паролю, клиент выбирает его и однократно передаёт пароль в подтверждённую форму, без повторного ввода. Капча и обязательный код остаются ручными шагами. Ошибка, отмена или переход к другому способу очищают отложенный пароль.
4. Пароль и код не сохраняются в настройках, аргументах процесса или логах. Команды передаются по приватному stdin-каналу, результаты — по приватному stdout-каналу. Буферы команд и нативных полей очищаются после использования и отмены.
5. При капче показывается оригинальный виджет VK в небольшой безрамочной карточке поверх клиента. Пользователь проходит её вручную; приложение не нажимает проверочные элементы и не подделывает результат. Фиксированные ограничения размера сохраняют маленький размер карточки на Wayland.
6. Незнакомые шаги, создание аккаунта и дополнительные согласия переводятся в ручной режим: пользователь может открыть оригинальную страницу VK. Подмены неизвестных форм нет.
7. После окончания формы аккаунт проверяется по собственным cookies webview. Навигация, смена cookies и появление проверки во время запроса отменяют устаревший результат. Затем helper закрывается и основное приложение загружает музыку.

У входа нет общего срока ожидания. При отмене прекращается попытка и закрывается helper. Закрытие карточки капчи возвращает управление нативному диалогу; её можно открыть снова.

## Границы доступа

Основное окно остаётся egui. Tauri работает в отдельном процессе того же исполняемого файла (`--web-login`), поэтому GTK/WebKit не блокирует цикл приложения. Локальные TCP-порты, sudo и собственный сервер не нужны.

Переходы и команды ограничены HTTPS-доменами входа VK. Страница не получает Tauri IPC или нативных команд. Запрос к полю связан с конкретным документом и версией формы; сменившаяся форма отвергает старую команду. Размеры сообщений ограничены, а капча и формы регистрации не принимают автоматическую отправку.

Профили обычных браузеров, их cookies, история и пароли не читаются. Импорта браузерных данных нет. Cookies собственного webview извлекаются нативным API, включая HttpOnly.

## Хранение и выход

На Linux пути начинаются с `$XDG_STATE_HOME/vk-fast`, если XDG-переменная содержит абсолютный путь; иначе — с `~/.local/state/vk-fast`. На Windows эти данные находятся в `config` рядом с `.exe`.

| Путь | Назначение |
| --- | --- |
| `webview/` | Собственный профиль webview, каталог 0700 |
| `webview/.login.lock` | Блокировка одновременного входа и очистки профиля |
| `music-session.json` | Профиль пользователя и собственные cookies VK, файл 0600 в каталоге 0700 |

«Выйти» удаляет сохранённую сессию и очищает собственный профиль webview под блокировкой. Файл блокировки остаётся, чтобы параллельный процесс не обошёл очистку созданием нового lock-файла. При ошибке очистки приложение сообщает об этом. Сессии и профиль обычных браузеров не изменяются.

Профиль webview и файл сессии содержат данные входа и не предназначены для публикации. Аудиокэш находится отдельно в пользовательском каталоге кэша и не содержит cookies, токенов или URL.

## Сборка

В проекте используются `tauri 2.12` с `wry` и `tauri-build 2`. Ресурсы `webview-assets` статические; `build.rs` вызывает `tauri-build`. Для обычного `cargo build --locked` не нужны Node.js, npm или установленный Tauri CLI.

Linux-webview требует GTK 3 и WebKitGTK 4.1. На Arch пакеты называются `gtk3` и `webkit2gtk-4.1`, на Debian/Ubuntu — `libgtk-3-dev` и `libwebkit2gtk-4.1-dev`. Нативные библиотеки обнаруживаются через `pkg-config`; зависимости окна и плеера приведены в [README](../README.md#что-установить). Требования webview сверены с [официальной инструкцией Tauri](https://v2.tauri.app/start/prerequisites/#linux).

## Другие способы входа

QR — отдельная кнопка с подтверждением на телефоне и ограниченным VK сроком действия самого QR. Он также создаёт собственную вебсессию приложения.

Старый VK ID OAuth доступен разработчику через `--oauth-login`: внешний системный браузер, PKCE, GitHub Pages и native callback `vkfast://`. Это отдельный механизм, который не запускается основной кнопкой. Опубликованная страница callback сохраняется; её наличие не означает, что Tauri-вход использует браузер или этот сайт.

## Проверки моста

`node scripts/test-login-bridge.mjs` проверяет локальные модели полей и виджета капчи без сетевых запросов. Node.js нужен только для этой проверки, а не для сборки или запуска плеера.

Отдельный игнорируемый Rust-тест `tauri_login::tests::local_hidden_webview_and_frameless_challenge_probe` проверяет скрытый webview и размер безрамочной карточки на локальной пустой странице. Для него нужна графическая сессия. Реальный вход в аккаунт проверяет его владелец.

Сохранённые пользователем материалы `vk-auth/` служат только локальной справкой и исключены из Git и архивов исходников.
