# VK Fast: вход из системного браузера без локального порта

Приложение VK Fast **54863250** уже создано. Новая сборка использует HTTPS-страницу возврата:

**https://eml3ss.github.io/vk-fast-auth/callback/**

Исходники страницы: [eml3ss/vk-fast-auth](https://github.com/eml3ss/vk-fast-auth), локальная копия — [browser-callback](../browser-callback/README.md).

## Однократное изменение в VK ID

В [кабинете VK ID](https://id.vk.ru/business/go) откройте существующее приложение **VK Fast / 54863250** и настройки Web-платформы:

- добавьте базовый домен **eml3ss.github.io**;
- добавьте доверенный Redirect URL **https://eml3ss.github.io/vk-fast-auth/callback/** — со слешем в конце;
- сохраните настройки.

Это бесплатный адрес GitHub Pages. Покупать домен, арендовать сервер или менять APP_ID не нужно. Владелец сообщил, что адрес добавлен в настройки нового приложения 54863250; принятие проверяется командой --check-registration. Готовые бинарники распространяются с одним APP_ID и одним HTTPS-адресом; слушателям музыки не нужно регистрировать собственные приложения.

## Как происходит возврат

1. VK Fast создаёт случайные state/verifier, формирует PKCE S256 и проверяет конфигурацию VK.
2. Системный `open::that` открывает браузер по умолчанию. Профили и CDP не создаются.
3. После подтверждения VK возвращает одноразовый code, state и device_id на GitHub Pages.
4. Страница очищает адресную строку, передаёт ответ по фиксированной ссылке `vkfast://oauth/callback` и предлагает ручную кнопку, если браузер ограничил автоматический запуск приложения.
5. Зарегистрированный обработчик передаёт URI ожидающему процессу через приватный Unix-сокет. Приложение проверяет URI и state, обменивает code с verifier и сверяет профиль.

Локальный TCP/HTTP-сервер не запускается. Порты, sudo и файловые capabilities для входа не требуются. Одновременные попытки входа в разных окнах разделены эксклюзивной блокировкой. Коды, URL возврата и токены в логи не выводятся; callback URI на диск не записывается.

Ранее сохранённые OAuth-токены сохраняют исходный redirect для refresh. Старый localhost может присутствовать в приватном файле сессии, но восстановление не открывает его порт. Вход через QR и его вебсессия работают независимо от HTTPS-страницы возврата.

## Обработчик ссылки на Linux

На этом компьютере обработчик уже установлен для текущего пользователя. При установке в другое место после сборки выполните без sudo:

```bash
scripts/install-auth-handler.sh /полный/путь/vk-fast
```

Скрипт создаёт пользовательский `vk-fast-auth.desktop` с обработчиком `x-scheme-handler/vkfast`. Обычный ярлык запуска приложения остаётся отдельным.

Проверки:

```bash
./target/debug/vk-fast --check-login
./target/debug/vk-fast --check-app-link
./target/debug/vk-fast --check-registration
```

Первая проверяет приватный канал без браузера, вторая передаёт синтетический ответ через системный обработчик приложения, третья проверяет принятие HTTPS redirect со стороны VK. Реальный вход нужно начинать кнопкой приложения; прямое открытие страницы GitHub Pages без ответа VK не выполняет авторизацию.

## Настройки сборки

```toml
[env]
VK_FAST_VK_CLIENT_ID = "54863250"
VK_FAST_VK_REDIRECT_URI = "https://eml3ss.github.io/vk-fast-auth/callback/"
```

Это публичные реквизиты. Client secret не нужен и в бинарник не включается. Зарегистрированное приложение и доступность для других аккаунтов контролируются владельцем в VK ID. Музыкальные возможности проверяются отдельно от успешного OAuth-входа.
