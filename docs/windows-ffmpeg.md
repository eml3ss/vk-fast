# Минимальный декодер FFmpeg для Windows

Portable-сборка VK Fast использует `bin/ffmpeg.exe` рядом с основным `vk-fast.exe`. Декодер собирается из исходников и затем переиспользуется в следующих выпусках; скачивать и устанавливать обычный пакет FFmpeg на компьютере пользователя не требуется. Программа запускается без консольного окна. Текущий каталог и системный `PATH` для поиска декодера в Windows не используются.

Вспомогательный процесс отделён от Rust-приложения. FFmpeg декодирует звук в поток PCM 48 кГц, stereo, float32; устройство вывода обслуживает Windows-бэкенд VK Fast. Основной интерфейс и логика остаются на Rust.

## Что включено

- Декодеры MP3, MP2, AAC / AAC LATM и PCM для аудиотестов.
- MP3, AAC, HLS, MPEG-TS, MP4 / fMP4 (`mov`) и WAV; необходимые вспомогательные демультиплексоры HLS включаются самим FFmpeg.
- HTTP / HTTPS, TCP / TLS, AES-128 HLS (`crypto`), файл и pipe для проверок. HTTPS использует статически встроенный Mbed TLS 3.6.7 со встроенным набором корневых сертификатов Mozilla; отдельные TLS DLL и файл сертификатов не нужны. Сертификат сервера и имя узла проверяются.
- Преобразование частоты и числа каналов, единственный выходной кодек `pcm_f32le` и сырой выход `f32le`.

Видеодекодеры, видеоэнкодеры, аппаратное ускорение, захват устройств, FFplay и FFprobe выключены. Небольшой набор общих фильтров выбирается зависимостями самой команды FFmpeg. Полный точный список компонентов сохраняется в `source/ffmpeg-configure-summary.txt` рядом с результатом сборки. Приложение по-прежнему ограничивает сетевой ввод списком протоколов `http,https,tcp,tls,crypto`.

Ранее декодер использовал Schannel. Полученный лог подтвердил отказ `InitializeSecurityContext` во время HTTPS-handshake до получения аудио. Замена TLS-бэкенда убирает этот участок зависимости от Windows; проверка сертификатов остаётся включённой. Переход требует заменить и основной `.exe`, и `bin/ffmpeg.exe` из нового архива.

## Воспроизведение сборки

На Linux x86_64 нужны `bash`, `curl`, `sha256sum`, `tar` с поддержкой xz/bzip2, `make`, Python 3, `patch` и хостовый GCC. Скрипт скачает переносимый LLVM-MinGW в `.build/windows-ffmpeg/tools`; системная установка компилятора Windows и права администратора не требуются.

```bash
./scripts/build-ffmpeg-windows.sh
```

По умолчанию используются четыре процесса сборки. Их можно изменить через `VK_FAST_JOBS`. `VK_FAST_FFMPEG_WORK` задаёт рабочий каталог, `VK_FAST_FFMPEG_OUTPUT` — каталог результата. По умолчанию результат находится в `target/windows-ffmpeg`:

```text
bin/ffmpeg.exe
licenses/ffmpeg/
source/BUILDINFO.txt
source/build-ffmpeg-windows.sh
source/ffmpeg-configure-summary.txt
source/ffmpeg-9.0.2.tar.xz
source/mbedtls-3.6.7.tar.bz2
source/ffmpeg-tls/
TLS-BACKEND.txt
```

Загрузки закреплены по версии и SHA-256; скрипт останавливается при несовпадении контрольной суммы. Для FFmpeg 9.0.2 исходный архив дополнительно проверен подписью официального ключа FFmpeg с отпечатком `FCF986EA15E6E293A5644F10B4322F04D67658D8`.

| Источник | Версия | SHA-256 |
| --- | --- | --- |
| [Исходники FFmpeg](https://ffmpeg.org/releases/ffmpeg-9.0.2.tar.xz) | 9.0.2 | `8c3850283eb25fa026482078a04051e0be17347b09ef81a0849bec15a96e002e` |
| [LLVM-MinGW](https://github.com/mstorsjo/llvm-mingw/releases/tag/20261020) | 20261020 UCRT, Ubuntu 22.04 x86_64 | `55064b60b991a1e1e8090b8c2f84e82b22cfe5903d12c159d65064cf5e8ae335` |
| [Mbed TLS](https://github.com/Mbed-TLS/mbedtls/releases/tag/mbedtls-3.6.7) | 3.6.7 | `a7e8bcbec0e6f761b4af24f25677626b35f762f68eef79c08677a363212d11f6` |
| [Mozilla CA bundle от curl](https://curl.se/docs/caextract.html) | 2026-10-20, 118 сертификатов | `796f1389bfea13c0ed78f663b765baaff54a508e5483786bd6ece73c5e3e3cbe` |

`scripts/ffmpeg-tls/prepare.py` проверяет хеши исходника, PEM и патча, затем создаёт C-заголовок со встроенными корнями. Патч добавляет корни только при отсутствии явного `ca_file`; проверки цепочки и имени узла выполняет Mbed TLS. Исходный PEM, MPL-2.0 и сведения о происхождении лежат рядом с патчем. Статические библиотеки Mbed TLS кэшируются отдельно; `build-windows.sh` переиспользует готовый декодер при совпадении маркера TLS-бэкенда. Старый Schannel-декодер пересобирается один раз.

Исходный архив FFmpeg содержит общие заголовки и систему сборки всего проекта. Он нужен на этапе компиляции, но в программе собираются только выбранные компоненты. Это отличается от загрузки полного готового пакета FFmpeg.

## Проверка декодера

Собранный PE x86_64 проверен под Wine на сгенерированном 12-секундном тоне, получаемом с локального HTTP-сервера. Во всех случаях использовались параметры приложения, включая входной `-ss 4`, выход stereo float32 / 48 кГц и сетевой список протоколов. Полученный PCM сопоставлялся с полным системным FFmpeg на Linux:

| Вход | Полный FFmpeg, секунд PCM | Windows audio-only FFmpeg, секунд PCM |
| --- | ---: | ---: |
| MP3 | 8,000000 | 8,000000 |
| HLS MPEG-TS + AES-128 | 8,986125 | 8,986125 |
| HLS fMP4 AAC | 8,010896 | 8,010896 |

Все шесть запусков исходного декодера завершились успешно. Проверка подтверждает одинаковое поведение аудиодекодеров; это не измерение точности перемотки. Входной `-ss` у HLS MPEG-TS в этом тесте следует временным меткам сегментов и сохраняет прежнее поведение Linux-версии. Его отдельное исправление не включено в перенос на Windows. После замены TLS-бэкенда проверки HTTPS повторяются отдельно, включая отказ для недоверенного сертификата. Импортируемые DLL остаются системными; DLL FFmpeg, Mbed TLS, OpenSSL и MinGW runtime не распространяются.

## Лицензии и исходники

Параметры `--enable-gpl --enable-version3` дают декодеру лицензию GPL версии 3 или новее, совместимую с GPL-3.0-only проекта VK Fast. Скрипт сохраняет исходные архивы FFmpeg и Mbed TLS, точные параметры сборки, рецепт, патч с доверенными корнями и тексты лицензий. Каталог `source` распространяется отдельным архивом соответствующих исходников вместе с выпуском. Официальные описания: [лицензирование FFmpeg](https://ffmpeg.org/legal.html), [сетевые протоколы и TLS](https://ffmpeg.org/ffmpeg-protocols.html#tls).
