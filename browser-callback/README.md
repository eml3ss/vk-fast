# VK Fast — статический возврат из браузера

Страница принимает одноразовый ответ VK и передаёт его обработчику **vkfast://oauth/callback** на этом компьютере. Она не объявляет вход завершённым: соответствие state, PKCE, обмен кода и проверку аккаунта выполняет приложение VK Fast.

Файлы подходят для HTTPS static hosting, включая бесплатный GitHub Pages. Здесь нет серверного приложения, npm-зависимостей, внешних шрифтов, аналитики, fetch-запросов, cookies или local/session storage. Публикация и изменение настроек VK этой папкой не выполняются.

## Размещение

Содержимое папки размещается в корне Pages-репозитория. Файлы **callback/index.html**, **callback/callback.js** и **callback/style.css** должны оставаться рядом. Файл **.nojekyll** отключает обработку Jekyll.

Для репозитория **eml3ss/vk-fast-auth** ожидаемый адрес:

[https://eml3ss.github.io/vk-fast-auth/callback/](https://eml3ss.github.io/vk-fast-auth/callback/)

Завершающий слеш важен: в кабинете VK и в запросе приложения должен совпадать полный адрес.

## Контракт

Поддерживаются плоские параметры **code**, **device_id**, **state** либо один JSON-параметр **payload** с теми же полями. Для отказа используются **state** и **error**. Текст error_description проверяется по размеру и отбрасывается. Метаданные провайдера, например type=code_v2, lang и source, игнорируются.

Успешный ответ передаётся только в таком виде:

    vkfast://oauth/callback?code=…&device_id=…&state=…

Отказ:

    vkfast://oauth/callback?state=…&error=access_denied

Важные поля ограничены 8192 печатными ASCII-символами; весь запрос и результирующий URI — 16384 символами. Дублирование важных полей, смешивание плоского ответа с payload, неполный ответ и fragment отклоняются. В JSON обнаруживаются также дубли с экранированными именами ключей.

Access/refresh/ID tokens, auth_info, другие токены, пароль, client secret и PKCE verifier не принимаются и не пересылаются. Неизвестный redirect_uri, next или другой URL не изменяет фиксированный адрес приложения.

Страница очищает query и fragment через history.replaceState до передачи в приложение. Значения кода, device_id, state и исходных ошибок не выводятся в текст страницы или логи. Выполняется одна автоматическая попытка открыть приложение. Если браузер её ограничивает, остаётся кнопка ручного открытия. Браузер или ОС могут запросить разрешение на внешний протокол.

Интерфейс RU/EN выбирается по языку браузера. Текст страницы не утверждает, что приложение уже получило ответ или завершило вход.

## Границы

Native-приложение обязано проверить случайный state ожидающей попытки, точный URI обработчика и PKCE. Страница не знает ожидаемый state и не может удостоверить его подлинность. Сам факт перехода из этой страницы не доказывает успешную авторизацию.

Начальный HTTPS-запрос с одноразовым кодом проходит через инфраструктуру хостинга до запуска JavaScript. Очистка адресной строки не удаляет возможные серверные журналы или историю первого запроса. PKCE verifier остаётся только в приложении; access/refresh tokens через страницу не передаются.

Meta CSP запрещает внешние ресурсы, fetch, формы, фреймы и объекты. Политика no-referrer запрещает отправку Referer. Директива frame-ancestors и X-Frame-Options требуют HTTP response headers: meta не заменяет их. GitHub Pages не предоставляет произвольные response headers, поэтому JavaScript дополнительно отказывается выполнять передачу из iframe. На хостинге с настраиваемыми заголовками добавьте:

    Content-Security-Policy: frame-ancestors 'none'
    X-Frame-Options: DENY

## Проверки

В отдельном репозитории страницы:

    node --test test/*.test.mjs

Из корня основного проекта:

    node --test browser-callback/test/*.test.mjs

Node.js нужен только разработчику для этих тестов; страница и Rust-приложение не требуют Node.js. Тесты используют синтетические данные, не открывают браузер и не запускают обработчик URI.

Локальный HTTP static server подходит для просмотра оформления. Передача настоящего ответа намеренно разрешена только через HTTPS и только в отдельной вкладке; HTTP preview не выполняет handoff.
